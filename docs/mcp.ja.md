# AI エージェントから使う (MCP)

AegisCMS には [MCP](https://modelcontextprotocol.io/)（Model Context Protocol）サーバーが組み込まれています。Claude Code や Cursor などの AI アシスタントが、スクリプトを挟まずにサイトの内容を読み、下書きを書けます。

- **アドレス**: サイトの `POST /mcp`（例: `https://example.com/mcp`）。トランスポートは Streamable HTTP で、サーバー側の追加設定は要りません。
- **認証**: **OAuth**（クライアントがサインイン画面を開き、あなたが「許可」を押します。[2 章](#2-oauth-でつなぐ)）か、[API トークン](content-api.ja.md#13-スクリプトciエージェント向けの-api-トークン)を `Authorization: Bearer aegis_pat_...` で送ります。どちらもなければ `401` です。
- **権限**: REST API と同じです。ツールはトークンのロールで動くので、同じ検査（ロール、レビューの流れ、入力の検証）を通り、ほかの変更と同じく[監査ログ](audit.ja.md)に残ります。

> [!IMPORTANT]
> 読み取りと下書きの保存は、訪問者には何も見えません。**公開、サイトから外す、削除**は別のツールで、`editor` のロールが要ります。OAuth では、サインイン画面の**公開**にチェックを入れたときだけ渡されます（既定はオフ）。アシスタントには、必要な範囲だけを渡してください。

## 1. つなぐ

1. API トークンを発行します（[Admin Studio › プロフィール › API トークン](admin-studio.ja.md#4-プロフィール)）。足りる範囲で一番低いロールを選びます。読むだけなら `viewer`、下書きを書くなら `contributor` か `editor` です。
2. クライアントにサーバーを追加します。Claude Code の例:

    ```bash
    claude mcp add --transport http aegiscms https://example.com/mcp \
      --header "Authorization: Bearer aegis_pat_..."
    ```

    URL とヘッダーを受け付けるクライアントなら、同じ 2 つの値を設定します。サイトをサブパスで公開している場合（[`[server].base_path`](configuration.ja.md)）は、`/mcp` の前に付けます。

3. アシスタントに頼みます。たとえば「下書きの記事を一覧にして」「新しいリリースについての記事を下書きで書いて」。

## 2. OAuth でつなぐ

Claude.ai のカスタムコネクタのように OAuth でサインインするクライアントは、サーバーのアドレス（`https://example.com/mcp`）だけで足ります。トークンを手で作る必要はありません。

1. クライアントがサインイン画面を自動で見つけ、ブラウザーで開きます。
2. 画面には、アプリの名前と求めている内容が出ます。**ユーザー名とパスワード**（二段階認証を使っていれば認証コードも）を入力して**許可**を押します。**拒否**を押すと、何も渡さずに戻ります。
3. クライアントに、アクセストークン（有効期間 **1 日**の API トークン）と**リフレッシュトークン**（有効期間 **90 日**）が渡されます。クライアントはリフレッシュトークンで、新しいアクセストークンを自動で取り直します。リフレッシュトークンは 1 回しか使えず、使うたびに新しいものに替わります。もう一度許可を求められるのは、アプリを 90 日使わなかったときだけです。

アプリができることは、2 段階で絞られます。許可した内容でトークンのロールが決まります。読み取りだけ（`content:read`）なら `viewer`、下書き（`content:draft`）なら `contributor`、公開（`content:publish`）とサイトの管理（`site:manage`。コメント、レビュー、注文、会員）なら `editor` です。アプリはそれぞれを求められますが、**下書きは既定でオン、公開とサイトの管理は既定でオフ**で、画面でチェックを入れて渡します。さらに、トークンはあなた自身のロールを超えません。

トークンは**プロフィール › API トークン**に `OAuth: <アプリ名>` として並び、いつでも失効できます。失効すると許可そのものが終わり、アプリはリフレッシュトークンでも新しいトークンを取れません。同じアプリをもう一度（たとえば別の端末で）許可すると、トークンがもう 1 つ増えます。

> [!NOTE]
>
> - この画面では、ユーザー名とパスワードでサインインします。サイトが OpenID Connect のシングルサインオンを使っているときは（[認証](authentication.ja.md#6-シングルサインオン-openid-connect)）、**Allow with <名前>** のボタンも出ます。IdP でサインインしたあと、画面で選んだ許可の内容のまま、アプリへ戻ります。始めたのと同じブラウザで最後まで行う必要があります。SAML のシングルサインオンは、この画面ではまだ使えません。[API トークン](#1-つなぐ)を使ってください。
> - サイトは `https://` で公開し、**正規 URL** を設定してください（[サイトの設定](admin-settings.ja.md)）。クライアントに伝えるサインイン画面のアドレスは、これから作られます。
> - エンドポイントは `/.well-known/oauth-protected-resource`、`/.well-known/oauth-authorization-server`、`/oauth/register`（動的クライアント登録）、`/oauth/authorize`、`/oauth/token` です。PKCE（`S256`）が必須です。

## 3. ツール

アシスタントには、トークンのロールで使えるツールだけが見えます。

### 読み取り（どのロールでも）

| ツール               | できること                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_content_types` | サイトのコンテンツタイプ（記事、固定ページなど）。                                                                                                      |
| `get_content_schema` | 1 つのコンテンツタイプのフィールド。                                                                                                                    |
| `list_content`       | タイプごとの一覧（新しい順）。本文のない要約です。`q`・`status`・`tag`・`category` で絞り、`limit`（既定 20、最大 100）と `offset` でページを送ります。 |
| `get_content`        | スラッグか ID で 1 件。本文のブロックとカスタムフィールドを含みます。                                                                                   |
| `list_tags`          | サイトのタグ。                                                                                                                                          |

読み取りで見えるものは、REST API と同じくトークンのロールで決まります。`viewer` のトークンには、Admin Studio で閲覧者に見える範囲が見えます。

### 下書き（`contributor` 以上）

どれも、訪問者に見える状態は作りません。

| ツール           | できること                                                                                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `create_draft`   | 新しい 1 件を、必ず**下書き**で保存します。`content_type`・`title`・`slug` が必須で、`blocks` と `fields` は任意です。                                                                                 |
| `update_content` | 既存の 1 件を変更します。変えたい項目だけ送ります。`title`、`slug`、`blocks`（本文を丸ごと置き換え）、`fields`（今のカスタムフィールドにマージ）が指定できます。                                       |
| `request_review` | 状態を**レビュー待ち**（`pending`）にします。`review_note` でメモも付けられ、編集者か校閲者が承認できるようになります。                                                                                |
| `set_tags`       | 1 件のタグを置き換えます。`tags` はタグのスラッグか ID のリストで、タグは先に作ってある必要があり、タグ機能が有効（`[tags].enabled`）でなければなりません（`list_tags`）。空のリストなら全部外します。 |
| `upload_media`   | 8 MB までの画像やファイルをアップロードし（`filename` と `data_base64`）、画像ブロックに入れる `url` を返します。それより大きいときは REST API を使います。                                            |

### 公開（`editor` 以上）

訪問者に見えるものを変えます。アシスタントには、あなたが頼んだときだけ使うよう伝えてあり、ツールは破壊的な操作として印が付くので、クライアントが確認を求めます。

| ツール              | できること                                                                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `publish_content`   | 1 件を今すぐ公開します。作業用のコピーを含め、最後に保存した版が公開版になります。`publish_at`（RFC 3339）を付けると、その日時に自動で公開されます。 |
| `unpublish_content` | 状態を `draft`（既定）か `archived`（`to`）にして、サイトから外します。内容は残ります。                                                              |
| `delete_content`    | 1 件を完全に削除します。                                                                                                                             |

### コメント・ショップ・会員（`editor` 以上）

訪問者や顧客の個人情報（コメント、注文、会員）と、公開の返信に触れます。OAuth では、サインイン画面の、コメントとレビューのモデレーションと注文・会員の参照の許可（`site:manage`、既定はオフ）にチェックを入れたときだけ渡され、書き込むツールはクライアントが確認を求めます。どれも、サーバーでその機能（コメント、ショップ、レビュー、会員）が有効でなければ使えず、無効のときは REST API のエラーで失敗します。

| ツール             | できること                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_comments`    | モデレーション用のコメントの一覧（新しい順）と、状態ごとの件数。`status`（`pending`・`approved`・`spam`・`trash`）、`content_type`、`content_id` で絞れます。 |
| `moderate_comment` | コメントの `status` を変えます。`approved` で公開され、ほかは非表示になります。                                                                               |
| `reply_to_comment` | 公開の返信を付けます（`body`、プレーンテキスト）。すぐ公開され、返信先のコメントも一緒に承認されます。                                                        |
| `list_orders`      | ショップの注文の一覧（新しい順。`status` で絞れます）。顧客の個人情報を含みます。                                                                             |
| `get_order`        | 注文 1 件の明細と顧客の情報。                                                                                                                                 |
| `sales_report`     | `start` から `end`（`YYYY-MM-DD`、UTC、両端を含む）までの、日別の売上。                                                                                       |
| `list_reviews`     | モデレーション用の商品レビューの一覧（`product_id`、`status` で絞れます）。                                                                                   |
| `moderate_review`  | レビューの `status` を変えます。却下するときは `rejection_reason` を付けます。                                                                                |
| `reply_to_review`  | レビューへの、ショップの公開の返信を設定します。                                                                                                              |
| `list_members`     | サイトの会員（訪問者のアカウント）の一覧。個人情報を含みます。                                                                                                |
| `get_member`       | 会員 1 人のレベルと状態。                                                                                                                                     |

商品はコンテンツなので、コンテンツのツール（商品のタイプでの `list_content`、`update_content`）で読み書きします。注文の状態の変更、返金、会員の変更は、MCP からはできません。

### 書き込みの動き

- **`create_draft` は必ず下書きで保存します。** 一緒に送った `status` や `publish` は無視されます。スラッグはタイプの中で重複できません。
- **`update_content` は状態を変えません。** 公開中の 1 件なら、変更は**作業用のコピー**として保存されます。`publish_content` で公開し直すか、人が Admin Studio で**公開版を更新**を押すまで、訪問者には公開版が見え続けます（[コンテンツを書いて公開する](admin-editing.ja.md#4-状態と公開)）。
- どのツールも、REST API と同じ検査を通ります。権限のないロール（たとえば、公開済みの他人の 1 件を公開・編集する `contributor`）は、ツールを直接呼んでも `403` で断られます。
- 本文はブロックのリストで、REST API と同じ形式です（[本文ブロックの仕様](content-api.ja.md#3-本文ブロックの仕様-blocks)）。形が分からないときは、似た 1 件を `get_content` で読ませてから書かせると確実です。

ツールが失敗したときは、REST API の HTTP ステータスとエラーメッセージがアシスタントに返ります（たとえば、スラッグがすでに使われていれば `409`、存在しない 1 件なら `404`）。

## 4. この版の制限

- ツールは上のものだけです。設定、ユーザー、テーマ、プラグイン、フォーラム、ニュースレター、問い合わせは MCP からは扱えません。Admin Studio か REST API を使ってください。
- サインイン画面は英語だけです。
- サイト全体で MCP を止めるには、`[mcp] enabled = false` にします（[設定リファレンス](configuration.ja.md#227-mcp--mcp-サーバー)）。`/mcp` と OAuth のエンドポイントは 404 を返します。特定のアシスタントだけを止めるときは、そのトークンを失効させます。
- 受け付けるのは `POST /mcp` だけです（サーバーからのストリームはありません）。`GET /mcp` は `405` を返します。
